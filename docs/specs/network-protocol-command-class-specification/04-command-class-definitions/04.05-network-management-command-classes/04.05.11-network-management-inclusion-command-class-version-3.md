# 4.5.11 Network Management Inclusion Command Class, version 3

## 4.5.11.1 Compatibility considerations

The Network Management Inclusion Command Class, version 3 is backwards compatible with the Network Management Inclusion Command Class, version 2.

A node supporting the Network Management Inclusion Command Class, version 2 MUST also support the Network Management Inclusion Command Class, version 2.

All commands and fields not mentioned in this version MUST remain unchanged from version 2.

The following command has been extended to support the report of a Smart Start node:

 [Node Add Status Command](04.05.11-network-management-inclusion-command-class-version-3.md#45112-node-add-status-command)

The following commands are introduced in order to support the Smart Start functionality:

 [Included Node Information Frame Report Command](04.05.11-network-management-inclusion-command-class-version-3.md#45113-included-node-information-frame-report-command)  [Smart Start Join Started Command](04.05.11-network-management-inclusion-command-class-version-3.md#45114-smart-start-join-started-command)

[Frame flows for the new functionalities of this Command Class are shown in 4.5.11.5 Usage and frame flows. A Z/IP Gateway MUST comply with 4.5.11.5 Usage and frame flows.](04.05.11-network-management-inclusion-command-class-version-3.md#45115-usage-and-frame-flows)

[A supporting node MUST issue the Node Add Status Command, Included Node Information Frame](04.05.11-network-management-inclusion-command-class-version-3.md#45112-node-add-status-command) [Report Command and the Smart Start Join Started Command to the first and the second unsolicited](04.05.11-network-management-inclusion-command-class-version-3.md#45113-included-node-information-frame-report-command) destinations.

4.5.11.1.1 Command Class dependencies A node supporting the Network Management Inclusion Command Class, version 3 MUST also support the Node Provisioning Command Class, version 1.

DSK Length (5 bits)

This field MUST indicate the length of the DSK field in bytes.

This field MUST be set to 0 if the added node does not support the S2 Command Class. This field MUST be set to 16 if the added node supports the S2 Command Class.

DSK (L bytes)

This field MUST advertise the DSK of the node that has been added to the network.

The length of this field (in bytes) MUST be according to the DSK Length field value. This field MUST be omitted if the DSK Length field is set to 0.

## 4.5.11.3 Included Node Information Frame Report Command

This command MUST be sent to the (first and second) unsolicited destinations when an Included NIF (INIF) is received and the following conditions are fulfilled:

 The advertised NHID matches an entry in the provisioning list  The advertised HomeID is different than the current network HomeID.

[A node issuing this command MUST subsequently issue a Node Provisioning Report Command for the](../04.07-node-provisioning-command-class-version-1.md#477-node-provisioning-report-command) matched entry in the provisioning list.

With the two commands, a Z/IP client can use the relevant information to guide the user on how to perform a reset operation on the device.

## 4.5.11.4 Smart Start Join Started Command

This command MUST be sent to the (first and second) unsolicited destinations when a Smart Start inclusion starts. The Add Node Status Command MUST be issued after the Smart Start inclusion and S2 bootstrapping attempts took place.
