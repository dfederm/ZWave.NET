# 4.5.10 Network Management Inclusion Command Class, version 2

## 4.5.10.1 Compatibility considerations

The Network Management Inclusion Command Class, version 2 is backwards compatible with Network Management Inclusion Command Class, version 1. A node supporting Network Management Inclusion Command Class, version 2 MUST also support Network Management Inclusion Command Class, version 1.

All commands not mentioned in this version remain unchanged from version 1.

The following commands are introduced to support the multiple security keys and DSK functionalities of the Security 2 Command Class:

 [Node Add Keys Report Command](04.05.10-network-management-inclusion-command-class-version-2.md#45104-node-add-keys-report-command)  [Node Add Keys Set Command](04.05.10-network-management-inclusion-command-class-version-2.md#45105-node-add-keys-set-command)  [Node Add DSK Report Command](04.05.10-network-management-inclusion-command-class-version-2.md#45106-node-add-dsk-report-command)  [Node Add DSK Set Command](04.05.10-network-management-inclusion-command-class-version-2.md#45107-node-add-dsk-set-command)

The following command has been extended to support the new S2/inclusion controller bootstrapping process:

 [Node Add Command](04.05.10-network-management-inclusion-command-class-version-2.md#45102-node-add-command)  [Node Add Status Command](04.05.10-network-management-inclusion-command-class-version-2.md#45103-node-add-status-command)  [Failed Node Replace Command](04.05.10-network-management-inclusion-command-class-version-2.md#45108-failed-node-replace-command)  [Failed Node Replace Status Command](04.05.10-network-management-inclusion-command-class-version-2.md#45109-failed-node-replace-status-command)

[Use-cases and frames flows for the new functionalities of this Command Class are shown in 4.5.10.10 Use cases and frame flows](04.05.10-network-management-inclusion-command-class-version-2.md#451010-use-cases-and-frame-flows)

## 4.5.10.2 Node Add Command

This command is used to add nodes to the Z-Wave network.

[The Node Add Status Command MUST be returned in response to this command unless it is to be](04.05.10-network-management-inclusion-command-class-version-2.md#45103-node-add-status-command) ignored.

This command MUST NOT be issued via multicast addressing. CC:0034.02.01.11.003 A receiving node MUST NOT return a response if this command is received via multicast addressing. The Z-Wave Multicast frame, the broadcast NodeID and the Multi Channel multi-End Point destination are all considered multicast addressing methods.

Grant CSA (1 bit)

This field is used to indicate if the S2 bootstrapping controller MUST allow CSA for Authentication. [(refer to [15]).](../04.16-zip-portal-command-class-version-1.md#4166-gateway-unregister)

The value 1 MUST indicate that the node MUST allow CSA. The value 0 MUST indicate that the node MUST NOT allow CSA.

Granted Keys (8 bits)

This field is used to indicate which network keys were granted during bootstrapping. [This field MUST be treated as a bitmask and comply with Table 28.](04.05.10-network-management-inclusion-command-class-version-2.md#45103-node-add-status-command)

This field MUST be set to 0x00 if the Accept field is set to 0.

Accept (1 bit)

This field is used to indicate if the S2 bootstrapping process is accepted by the user and must continue.

The value 0 MUST indicate that the S2 bootstrapping is not accepted and MUST be interrupted. The value 1 MUST indicate that the S2 bootstrapping is accepted and MUST continue.

This field indicates the length in bytes of the DSK input by the user.

This field MUST be set to the same or a higher value than the ”Input DSK Length” field value received in [the Node Add DSK Report Command that caused this command to be returned.](04.05.10-network-management-inclusion-command-class-version-2.md#45106-node-add-dsk-report-command)

Input DSK (N bytes)

This field indicates the DSK input by the user. A receiving node (Z/IP gateway) MUST overwrite the part of the DSK with the Input DSK contained in this frame

The length of this field in bytes MUST be according to the Input DSK Length field value. If the Input DSK Length is set to 0, this field MUST be omitted.

Accept (1 bit)

This field is used to indicate if the DSK Report is accepted by the user and if S2 bootstrapping must continue.

The value 0 MUST indicate that the DSK Report is not accepted and S2 bootstrapping MUST be interrupted. The value 1 MUST indicate that the DSK Report is accepted and S2 bootstrapping MUST continue.

[silabs.com | Building a more connected world.](https://www.silabs.com/) Page 96 of 196 4.5.10.10.2 Z/IP Client with an S2 inclusion controller including an S2 node

When performing S2 bootstrapping, the unsolicited destination of the Z/IP Gateway will receive a unsolicited Node Add S2 Keys Report from the Z/IP Gateway. The Z/IP Client at this point has two options:

1. Automatically grant requested S2 Classes without presenting a user dialog in the S2 Keys Report step. In this case, the Z/IP Client MUST present a user dialog in next step before sending the DSK Set 2. Using advanced joining where the user MUST confirm the specific keys being requested in a dialog, before continuing to next step. In this case, the Z/IP MAY present a user dialog in next step before sending the DSK Set, if required by the S2 Classes being granted.

This is done without the SIS having entered Add Node mode. From this point on the S2 inclusion frame flow is same as when including through the SIS.
