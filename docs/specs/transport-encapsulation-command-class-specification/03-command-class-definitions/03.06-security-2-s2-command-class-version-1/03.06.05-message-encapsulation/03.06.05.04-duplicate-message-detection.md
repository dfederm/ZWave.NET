# 3.6.5.4 Duplicate Message Detection

A sending node MUST set the Sequence Number to a random value on startup. The Sequence Number MUST be incremented for the transmission of each new unique singlecast (and singlecast follow-up) transmission.

A receiving node MUST use the Sequence Number field in the Nonce Get, Nonce Report and Message Encapsulation commands for duplicate detection. Duplicates of recently received commands MUST be discarded.

The following algorithm SHOULD be used for duplicate detection of singlecast messages:

1. If an incoming sequence number and Peer NodeID match an entry in the SPAN table, the frame MUST be discarded. 2. If it is a new sequence number, the received sequence number and Peer NodeID MUST be stored in the SPAN table.
